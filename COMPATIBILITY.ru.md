# Совместимость CSQTT 2.5.0 с 2.1.9, Windows и iOS

Изменения подготовлены на основе приложенного `csqtt-main.zip`. Код этого архива и
`csqtt-2.5.0.zip` совпадает. Это исходники совместимой сборки, а не готовый APK.

Установка сервера одной командой, без ручного переноса файлов:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash
```

Подробности: [INSTALL.ru.md](INSTALL.ru.md).

## Что работает

| Подключение | Реализация |
| --- | --- |
| Android CSQTT 2.1.9 → изменённый сервер 2.5 | Старый GETCONF с device_id; CSQTT-WIRE-2/3; ChaCha-аудио и AES-видео |
| focsq Windows/Linux → изменённый сервер | Тот же versioned GETCONF и CQF1, до 126 потоков |
| VK TURN Proxy iOS → изменённый сервер | CSQTT-WIRE-2/3, аудио/видео и отдельная ссылка импорта vkturnproxy:// |
| Android CSQTT 2.5.0 → изменённый сервер | Существующий DTLS и формат данных 2.5 |
| Изменённый клиент → сервер 2.1.9 | Автоматическая повторная регистрация через WRAP и CSQTT-WIRE-2 |

Клиенты Windows/iOS сверены по исходникам проектов, указанных в README:

- [focsq](https://github.com/luminescq/focsq/tree/9ad3bfb36e7ed5717b3ee2766e53a59ddf2fbad5), `backend/protocol.rs`, `backend/wrap.rs`.
- [vk-turn-proxy-ios](https://github.com/anton48/vk-turn-proxy-ios/tree/bea60aad52424efb3ddfabc532a1069bba3b96e4), `pkg/csqtt/control.go`, `wrap.go`, `frame.go`.

Из сторонних клиентов не переносился код: использованы их публичные форматы сообщений.
CQF1-модуль восстановлен из предоставленного исходного кода CSQTT 2.1.9.

## Как подключаться

Обновлённая панель позволяет выбрать **2.1.9 / 2.5.0** перед копированием ссылки
или открытием QR-кода. Пошаговая инструкция: [PANEL.ru.md](PANEL.ru.md).
Этот выбор задаёт формат импорта, сервер продолжает принимать обе версии одновременно.

1. Установите изменённый сервер вместо исходного сервера CSQTT 2.5. Для уже
   установленных приложений 2.1.9, focsq и VK TURN Proxy менять их код не требуется.
2. На индивидуальной странице подписки сервера выберите приложение. QR-код,
   копирование и кнопка открытия используют выбранный формат:
   Android 2.5 — исходную запечатанную ссылку; старый Android/focsq —
   `csqtt://connect?...`; iOS — `vkturnproxy://import?data=...` со всеми VK-ссылками.
   JSON индивидуальной подписки дополнительно содержит `legacy_link` и `ios_link`.
3. Для старых клиентов задайте ссылки VK-звонков. Один только VK access token
   из настройки Android 2.5 не заменяет эти ссылки в старом клиенте; при отсутствии
   хешей их нужно добавить в настройках Windows/iOS.
4. Для подключения изменённого клиента к старому серверу оставьте режим SRTP
   `auto`. Сначала он пробует DTLS/формат 2.5, затем совместимый WRAP/формат 2.1.9.
   Первое подключение к старому серверу может занять около 10 секунд.
   В режиме `dtls` автоматического перехода на старый протокол нет.

Android передаёт прежний `ANDROID_ID` как `--device-id`. Для CLI можно явно указать
`--device-id <идентификатор>` или переменную `CSQTT_DEVICE_ID`. Если старый сервер
уже привязал пароль к другому device_id, необходимо использовать прежний
идентификатор или снять привязку в его панели. Ошибка `device_mismatch` считается
ошибкой авторизации, а не поводом бесконечно переподключаться.

Сервер выбирает способ передачи отдельно для каждого подключения: новые
фрагменты `0xCF` остаются у нового клиента; старому клиенту передаётся целый IP-пакет,
а клиенту CSQTT-WIRE-3 — CQF1 для TCP. Смена DNS сохраняет этот выбор.
Порядок CQF1 восстанавливается с ограничением памяти и изоляцией разных клиентов.
Проверка пароля, срока действия, блокировки и RTP replay-защита сохраняются.
Старая криптография работает только на соответствующем старом подключении.

## Сборка

Нужны Rust 1.97.1 и зависимости сборки из проекта. Проверка в Linux:

```bash
cargo test --manifest-path rust-server/Cargo.toml --target x86_64-unknown-linux-gnu --locked
cargo test --manifest-path rust-client/Cargo.toml --locked
```

Сервер для текущего Linux-хоста:

```bash
cargo build --manifest-path rust-server/Cargo.toml --target x86_64-unknown-linux-gnu --release --locked
```

Для статических серверов amd64/arm64/armv7 используйте существующий
`bash rust-server/build_linux.sh --tests` с Zig/cargo-zigbuild и PowerShell для provenance.
Для Android используйте существующие `rust-client/build_so.bat` и
`scripts/build_apk.bat` с SDK/NDK и собственной настройкой подписи.
Необходимо пересобрать нативный клиент и серверные assets; исходные provenance-файлы
относятся к оригинальным бинарникам. Сценарии provenance теперь учитывают все
исходники в `shared`, включая новый код совместимости.

В архиве исходников нет APK, подписывающих ключей и готовых server/native assets.
`local.properties` исключён: пути SDK и параметры подписи задаются на машине сборки.
Проверки provenance отключать не нужно.

## Проверки и границы результата

- Сервер: **181 тест пройден**, 1 внешний сценарий и 2 ручных CPU-замера пропущены в обычном запуске.
- Rust-клиент: **391 тест пройден**, 11 внешних сценариев и 2 ручных CPU-замера пропущены в обычном запуске.
- CPU-замеры запущены отдельно: [разбор и результаты оптимизации](PROTOCOL.ru.md).
- Импорт Android: **18 тестов JUnit пройдено** на JVM с Kotlin 2.4.0;
  для Android Build/Base64 использованы локальные тестовые заглушки.
- Проверены исходный зашифрованный GETCONF 2.1.9 и опубликованные Go-векторы
  аудио/видео, включая побайтовое совпадение обратного шифрования.
- Локальный UDP/TURN-сценарий проверяет автоматический переход нового клиента на
  старый серверный формат, передачу и возврат 1500 байт в аудио/видеорежимах,
  корректный DISCONNECT по device_id.
- Серверные сценарии проверяют WIRE-2/3, числовой пароль, 1500 байт без новых
  фрагментов, порядок CQF1, replay и подмену внутреннего IPv4-источника.

Полный APK не собирался; GUI приложений на физических Windows/iOS и внешний
VK TURN в этой среде не запускались. Проверена совместимость форматов и локальный
обмен данными. Итоговый APK требует штатной сборки и проверки на устройствах.
