## Главное для вашей задачи

В текущем swg-panel **нет общей совместимости 2.1 ↔ 2.5**. Панель хранит две
линии сервера и предлагает соответствующие приложения. В тесте
`tests/spa_csqtt_ios_links_selftest.mjs` прямо проверено: для линии 2.5 выдаётся
только новый Android CSQTT, для 2.1 доступны также focsq и VK TURN Proxy iOS.
Смена линии с сохранением пользователей не означает совместимость протоколов.

Что полезно в этом репозитории:

- [csqtt-2.5.1-2](https://github.com/SanityProtocol/swg-panel/releases/tag/csqtt-2.5.1-2)
  — форк сервера на основе amurcanov 2.5.0, интеграция с панелью и исправление
  распределения объёмного UDP-трафика. Суффикс `-2` убирает ненужный вывод пароля
  отключённой web-панели и исправляет сообщение о её адресе.
- [csqtt-app-2.5.1](https://github.com/SanityProtocol/swg-panel/releases/tag/csqtt-app-2.5.1)
  — Android-форк с исправлениями отдачи, Wi-Fi auto-pause и плитки быстрых настроек.
  Собственный application ID `net.sanityprotocol.csqtt` и собственная подпись.
  Он рассчитан на серверную линию 2.5.
- [csqtt-app-2.1.9](https://github.com/SanityProtocol/swg-panel/releases/tag/csqtt-app-2.1.9)
  — зеркало исходных APK 2.1.9 без изменений, для линии 2.1.
- Для iOS панель формирует `vkturnproxy://import?data=...` и передаёт все ссылки
  VK-звонков. Прямой импорт одной ссылки CSQTT в iOS может сохранить только первый
  звонок. Этот формат учтён в совместимой сборке исходного CSQTT.

## Как совместить с подготовленными изменениями

Патч совместимости подготовлен к приложенному исходному CSQTT 2.5.0/main.
Он не заменяет swg-panel-патч: форку нужны `--iface`, `--tun-addr`, `--no-nat`,
`--no-web`, `--desired`, работа с желаемыми пользователями и проверки источника IP.
Замена управляемого бинарника на обычный upstream-бинарник нарушит этот интерфейс.

При переносе в swg-panel нужно объединить изменения `rust-server/protocol.rs`,
подключить `shared/compat.rs` и `shared/flow_frame.rs`, сохранить их интеграционные
параметры и источник IPv4 из аутентифицированной сессии. Для новой совместимой
сборки затем потребуется явно разрешить старые клиенты в каталоге панели;
текущие штатные сборки линии 2.5 по-прежнему должны иметь прежнее ограничение.

Код панели и её серверного форка в этой работе не изменялся. Серверные исправления
скорости из swg-panel также не переносились: это отдельное изменение поведения
планировщика, не требуемое для совместимости форматов.
