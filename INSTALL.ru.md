# Установка совместимого CSQTT одной командой

Файл `install-csqtt.sh` автономный: внутри находятся исходники совместимой версии,
LICENSE и контрольная сумма архива. Он собирает именно эту версию, устанавливает
зависимости и запускает `csqtt.service` с автозапуском после перезагрузки.

## На VPS

Вставьте эту команду в терминал сервера:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash
```

Файлы на сервер вручную копировать не нужно. Загрузчик скачает автономный
установщик с GitHub, проверит SHA-256 и запустит его. Если вы вошли как root,
установка начнётся сразу; для обычного пользователя используется sudo.

Репозиторий: [mikhail384/tunnelscope, ветка csqtt-compatible](https://github.com/mikhail384/tunnelscope/tree/csqtt-compatible).
В ней находятся полный исходный код, лицензия и оба установочных файла.

Поддерживаются Ubuntu/Debian с systemd, amd64 и arm64. Нужен интернет для загрузки
Rust 1.97.1 и зависимостей; для сборки рекомендуется от 2 ГБ RAM и 4 ГБ свободного
места. Первая установка занимает время на компиляцию. Готовый сервер и Rust-кэш
сохраняются, чтобы повторная сборка выполнялась быстрее.

В конце выводятся адрес HTTPS-панели, логин, пароль панели и пароль подключения.
Откройте панель, добавьте VK-ссылки и создайте подключения для нужных приложений.
На странице подписки доступны форматы для Android 2.5, Android 2.1.9/focsq и iOS.

По умолчанию сервер использует **46000/UDP**, панель — **46002/TCP**. Установщик
добавляет правила firewall на самом VPS. В security group или firewall провайдера
эти порты также должны быть разрешены. Для панели используется существующий
сертификат либо автоматически создаётся самоподписанный HTTPS-сертификат.

## Установка из сохранённого файла

Автономный `install-csqtt.sh` можно сохранить и запустить без загрузчика:

```bash
sudo bash install-csqtt.sh
```

Либо передать его с компьютера по SSH одной командой.

В Bash на Linux/macOS, из каталога с загруженным файлом:

```bash
ssh root@IP_СЕРВЕРА 'umask 077; f=$(mktemp) || exit; cat >"$f" && bash "$f"; r=$?; rm -f "$f"; exit "$r"' < install-csqtt.sh
```

Замените `IP_СЕРВЕРА` на адрес VPS. Команда передаст файл через SSH, установит
сервер и удалит только временный файл установщика. Доступ root по SSH должен
быть настроен на вашем сервере.

## Необязательные настройки

Например, выбрать порты и публичный IPv4:

```bash
sudo env CSQTT_PEER_PORT=46000 CSQTT_WEB_PORT=46002 CSQTT_PUBLIC_IP=203.0.113.10 bash install-csqtt.sh
```

Замените адрес примера на реальный. Если `CSQTT_PUBLIC_IP` не задан, установщик
определит его автоматически. Для ограничения параллельной сборки можно передать
`CSQTT_BUILD_JOBS=1`. Пароли генерируются автоматически; при необходимости
можно задать `CSQTT_WEB_USER`, `CSQTT_WEB_PASS`, `CSQTT_MAIN_PASSWORD`.

## Обновление и сохранение данных

Повторно выполните ту же команду. Существующая служба работает, пока собирается
и проверяется новый бинарник. Перед заменой создаётся резервная копия бинарника,
unit-файла, конфигурации и базы в `/var/backups/csqtt-compatible/`.
Сохраняются действующие пароли, база и порты штатного systemd-сервера.

После замены проверяются служба systemd, TUN, UDP и HTTPS. При неудаче установщик
восстанавливает прежние файлы и запускает прежнюю службу, если она работала.
Чужой процесс, занимающий нужный порт, автоматически не завершается.

Основные пути:

- `/usr/local/bin/csqtt` — сервер;
- `/etc/csqtt/compatible.env` — параметры и пароли, доступ только root (0600);
- `/etc/csqtt/csqtt.db` — база;
- `/etc/systemd/system/csqtt.service` — служба;
- `/usr/local/share/csqtt-compatible/source` — установленные исходники и лицензия.

Статус: `systemctl status csqtt`. Журнал: `journalctl -u csqtt -f`.

Для экземпляра, управляемого **swg-panel**, нужен перенос совместимости в их форк:
этот установщик предназначен для обычного CSQTT и откажется заменять обнаруженный
управляемый unit. См. `SWG_PANEL_REVIEW.ru.md`.

## Проверка и пересборка установщика

```bash
bash install-csqtt.sh --help
bash install-csqtt.sh --extract ./csqtt-source
python3 scripts/package_installer.py ./install-csqtt.sh --bootstrap ./install.sh
python3 -m unittest discover -s tests -v
```

В полном каталоге исходников также можно выполнить
`sudo bash scripts/install-server.sh`; он использует локальные файлы проекта.

Проверено в этой работе:

- тесты конфигурации, обновления, отката, сохранения паролей, проверки портов
  и автономного архива; повреждённый архив отклоняется до извлечения;
- сборка release-сервера из встроенного архива установщика на Linux amd64;
- полная установка опубликованной командой из GitHub в изолированной Ubuntu
  24.04 с systemd: загрузка Rust и зависимостей, сборка сервера, запуск службы
  без перезапусков и встроенные проверки TUN, UDP и HTTPS;
- реальная установка и обновление службы в изолированной Ubuntu 24.04 с systemd,
  создание TUN, открытие UDP и проверка HTTPS с локальным сертификатом;
- намеренно неисправный кандидат: восстановлены прежний бинарник, unit и
  параметры; прежняя служба снова работает;
- пароли сохраняются при повторной установке.

Arm64 и другие версии Ubuntu/Debian в этой проверке отдельно не запускались.
Автономный установщик можно распространять отдельно: рядом с ним не нужны
дополнительные файлы. При изменении сервера пересобирайте оба установочных файла
одной командой выше, чтобы загрузчик содержал актуальную контрольную сумму.
