# Локальная копия и возврат на CSQTT 2.1.9

Услуга бэкапов у хостера не требуется. Копии хранятся на самом VPS в
`/var/backups/csqtt-compatible/`, с доступом только для root.

## Сохранить текущий CSQTT перед обновлением

В терминале сервера выполните одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash -s -- --backup
```

Команда ненадолго останавливает CSQTT, копирует согласованную базу, настройки,
пароли, серверный бинарник, unit-файл и управляемые сетевые файлы, затем запускает
службу обратно, если она работала. Она выводит путь к копии. Новые копии содержат
версию программы и SHA-256 файлов. Сборка сервера и установка зависимостей
для этой операции не выполняются.

Если сейчас установлен **CSQTT 2.1.9**, эта команда создаст точку возврата на 2.1.9.
Если сейчас установлена **2.5.0**, она сохранит 2.5.0: команда резервного копирования
не может создать прежнее состояние, которого на сервере уже нет.

## Вернуть 2.1.9

Запускайте эту команду только когда хотите выполнить откат:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash -s -- --rollback 2.1.9
```

Выбирается последняя исправная локальная копия с подтверждённой версией 2.1.9.
При отсутствии такой копии команда завершается **до остановки работающего сервера**.
Поддерживаются также копии, созданные прежними версиями нашего установщика:
у них проверяются структура, база SQLite и фактическая версия бинарника.

Перед заменой автоматически сохраняется текущее состояние в ещё одну локальную
копию. Затем возвращаются сервер, панель, база, пароли, настройки и состояние
автозапуска выбранной копии. Проверяются стабильность службы и принадлежность
портов UDP/TCP её процессу. Если восстановленный сервер не запускается, возвращается
состояние перед попыткой отката.

**Доступы и изменения, появившиеся после выбранной копии, не будут активны в
восстановленной базе.** Они сохранятся в копии, созданной перед откатом; её путь
выводится в терминале. После успешного отката используйте прежние адрес и пароль
панели. Если на момент выбранной копии служба была остановлена, она останется
остановленной; команда сообщит, как запустить её.

## Список копий и восстановление конкретной

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash -s -- --list-backups
```

Выводит имена каталогов, версии и результат проверки, без паролей. По точному
имени можно вернуть в том числе состояние 2.5.0, сохранённое перед откатом:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/csqtt-compatible/install.sh | bash -s -- --rollback ИМЯ_КОПИИ
```

Замените `ИМЯ_КОПИИ` на имя из списка. Повреждённая или неполная выбранная копия
отклоняется до изменения файлов. Установка и откат используют общий lock,
поэтому одновременно запустить их нельзя.

## Без сети и границы восстановления

Заранее сохранённый автономный установщик версии `2.5.0-compatible.3` и новее
поддерживает те же операции без скачивания исходников и Rust:

```bash
sudo bash install-csqtt.sh --backup
sudo bash install-csqtt.sh --list-backups
sudo bash install-csqtt.sh --rollback 2.1.9
```

Нужны Python 3, systemd и обычная установка CSQTT в `/etc/csqtt`,
`/usr/local/bin/csqtt` и `/etc/systemd/system/csqtt.service`.
Экземпляры под управлением swg-panel и Docker автоматически не заменяются.
На диске должно хватать места для копии текущей базы и бинарника.

Это копия CSQTT, а не снимок всего VPS. Она не восстанавливает настройки хостинга,
пакеты ОС и другие приложения. При потере самого диска VPS локальная копия тоже
будет потеряна; важную копию можно дополнительно скачать на свой компьютер по SFTP.

## Проверка

Пройдены 32 теста установщика, упаковки и восстановления. В изолированной Ubuntu
24.04 с systemd проверен цикл с настоящими бинарниками 2.1.9 и совместимым 2.5.0:
локальная копия, обновление, откат, возврат к состоянию перед откатом, вход в обе
панели с прежними учётными данными и состав доступов. Дополнительно проверены отказ
от повреждённой копии без остановки службы и автоматическое восстановление текущей
2.5.0 после неудачного запуска сохранённой старой версии.
