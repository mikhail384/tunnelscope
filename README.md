# TunnelScope

**Проект создан с помощью ИИ — OpenAI Codex.**

Панель мониторинга VPN для Ubuntu: клиенты, соединения, домены, владельцы IP,
общие и персональные ограничения скорости и списки запрещённых сайтов.
Интерфейс на русском языке. Python использует только стандартную библиотеку.

## Установка одной командой

На Ubuntu 22.04 / 24.04 с systemd и установленным curl:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/main/install.sh | sudo bash
```

Команда устанавливает недостающие системные зависимости, копирует приложение в
`/opt/tunnelscope`, создаёт пользователя и три службы, а затем выводит адрес панели
и случайный пароль. Существующие настройки, история и пароль сохраняются при обновлении.
Копии кода находятся в `/var/backups/tunnelscope`, настроек — в `/etc/tunnelscope/install-backup-*`.

Новая установка открывает **HTTPS на порту 9180** с самоподписанным сертификатом.
Браузер попросит подтвердить доверие сертификату. При сетевом firewall разрешите
TCP 9180. Для публичного сервиса можно поставить свой HTTPS reverse proxy.
Установка поверх существующей панели сохраняет её адрес, сертификат и настройки proxy.
VPN-протоколы, nginx и чужие правила firewall установщик не перенастраивает.

Повторно посмотреть данные входа:

```bash
sudo cat /etc/tunnelscope/access.txt
```

Порт и адрес привязки для **первой** установки можно изменить:

```bash
curl -fsSL https://raw.githubusercontent.com/mikhail384/tunnelscope/main/install.sh | sudo env TUNNELSCOPE_PORT=9280 TUNNELSCOPE_BIND=127.0.0.1 bash
```

Для установки из локальной копии: `sudo env TUNNELSCOPE_SOURCE="$PWD" bash install.sh`.
Старую директорию `/opt/tunnelscope` не используйте как источник для неё самой.

## Возможности панели

- Счётчики клиентов 3x-ui / Xray, CSQTT, Mieru; наблюдение TCP/UDP на обнаруженных интерфейсах.
- DNS, HTTP Host и TLS SNI, фильтры соединений, история, графики, CSV и переименование клиентов.
- Определение ASN и оператора сети через RIPEstat: отправляется только IP назначения.
- Переход к панелям протоколов через настраиваемые ссылки.
- Отдельные лимиты скачивания и отдачи, общий порог и персональные значения.
- Общие и персональные списки доменов: обращение отключает интернет клиента до ручного разрешения.
- Исключения для клиентов, переключатели правил и кнопка восстановления доступа.
- **Импорт TXT и Word DOCX** в общий либо персональный список. Файлы `.docs` принимаются,
  если внутри находится текст или DOCX. Старый бинарный `.doc` сначала сохраните как `.docx`.

В окне «Мои запрещённые сайты» нажмите **«Загрузить TXT / Word»**. Импорт добавляет
домены к текущему черновику, удаляет повторы и сообщает о пропущенных записях.
Проверьте результат и нажмите «Сохранить список». Загрузка сама по себе не включает правило.
Поддерживаются ссылки, домены на кириллице, строки hosts и комментарии `#`.
Ограничения: 512 КБ на файл, 100 разных доменов на один список, 2000 доменов всего.
TXT читается в UTF-8, UTF-16 с BOM и Windows-1251. Файлы не сохраняются на сервере.

Разделы блокировки приложений, Supercell и 18+ удалены из интерфейса.
Серверный код прежних правил сохранён для совместимости с существующими установками;
в новых конфигурациях эти правила выключены. Импорт относится к вашим собственным спискам сайтов.

## Конфигурация и службы

- `/etc/tunnelscope/web.json` — доступ, HTTPS и хранение истории.
- `/etc/tunnelscope/collector.json` — источники, интерфейсы, ссылки `panel_links` и правила.
- `/var/lib/tunnelscope/history.db` — история. По умолчанию 14 дней и до 100000 потоков.
- `/var/lib/tunnelscope-policy/` — приватное состояние ограничений.
- `tunnelscope-web`, `tunnelscope-control`, `tunnelscope-agent` — службы панели.

Список интерфейсов обнаруживается при первой установке. Путь к существующим базам
3x-ui и CSQTT можно изменить в `collector.json`. Mieru читается через `mita`.
Для доменных правил и лимитов Xray нужен работающий локальный API Xray с outbound
`blocked` и совместимой маршрутизацией. Установщик не включает API и не меняет конфигурацию VPN.
Если ядро использует другой порт, задайте `xray_api`, `xray_binary`, `xray_config`.

Просмотр состояния и перезапуск панели:

```bash
sudo systemctl status tunnelscope-web tunnelscope-control tunnelscope-agent
sudo systemctl restart tunnelscope-web tunnelscope-control
sudo systemctl restart tunnelscope-agent
```

При размещении за nginx задайте для отдельного location панели `client_max_body_size 1m`,
`proxy_read_timeout 60s` и `X-Forwarded-Proto https`. Пример конфигурации источников:
[config.example.json](config.example.json).

## Границы точности

HTTPS не расшифровывается. Фоновое обращение к домену не доказывает посещение сайта
человеком. ECH, QUIC, DoH, вложенные туннели и общие CDN ограничивают распознавание.
Владелец IP может быть хостингом, а не владельцем сайта. Для журнала Xray нет
достоверного счётчика байтов каждого домена; общий трафик берётся из счётчиков VPN.

Правила применяются только при надёжной привязке к клиенту: Xray по учётной записи,
индивидуальный CSQTT / WireGuard — по адресу и типу туннеля. Mieru поддерживает
ограничения только при одном пользователе. Общие контейнерные мосты не блокируются
как одно устройство. Новые соединения Xray получают лимит после переподключения.

## Проверка и сборка

```bash
python3 -B -m unittest discover -s tests -q
node --check static/app.js
bash -n install.sh
python3 -B deploy/package.py
```

GitHub Actions проверяет код, чистую установку на Ubuntu, HTTPS, авторизацию,
импорт документов и повторную установку с сохранением конфигурации.
Архивы появляются в `dist/`. Данные доступа, приватные профили, базы и снимки экрана
не входят в Git-репозиторий. Источники стороннего каталога перечислены в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
